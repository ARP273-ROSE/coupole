\section{Overview}
Coupole is a free application (GPL-3.0) written in Python 3.10+, running on Windows, macOS and Linux, with a
graphical interface (PyQt6) and a complete command line. Every displayed text exists in French and English; the
system language is detected and can be forced (\emph{Language} menu, Preferences, or \cmd{--lang fr|en}).

\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lX@{}}
\toprule
\textbf{Module} & \textbf{Purpose}\\
\midrule
OHP image bank & Inventory, catalogue, download, astrometric check, fixed headers, conversion, stackable sets, anomalies, sky map.\\
Image quality & Optional. FWHM, ellipticity, background, noise, gradient, saturation, trails, sampling.\\
Spectra and series & Reading and plotting 1D data (radio spectra, light curves, tables).\\
Cosmology & From redshift to distances, ages, volume, distance modulus, scale (Planck 2018 and others).\\
Sites and times & Site database, OpenStreetMap map, UTC and local time.\\
My computer & Hardware diagnosis; minimal example module.\\
\bottomrule
\end{tabularx}
\end{center}

Principles: all long work runs off the GUI thread (the interface stays responsive, with progress and
cancellation); an interrupted run resumes where it stopped; nothing is deleted without a trace; no data is sent
without consent; optional components (ASTAP, SEP, CuPy) may be missing.

\subsection{With the computer's Python}
The scripts in the source folder look for Python 3.10 or newer, create a virtual environment, install the
dependencies and create launchers. One question only: Enter to confirm (\cmd{--oui} / \cmd{-Oui} to skip it).
\begin{ccode}
sh install.sh                \# Linux, macOS\\
install.bat                  \# Windows (double-click; runs install.ps1)
\end{ccode}
Without Python, or without the \texttt{venv} module (Debian: \texttt{python3-venv} package), the script says so and
explains how to get it. Locations: Linux \texttt{\textasciitilde/.local/share/coupole/venv}, launchers in
\texttt{\textasciitilde/.local/bin}; macOS \texttt{\textasciitilde/Library/Application Support/Coupole/venv} and
\texttt{\textasciitilde/Applications/Coupole.app}; Windows \texttt{\%LOCALAPPDATA\%\textbackslash
Programs\textbackslash CoupolePython}, Desktop and Start menu shortcuts.

\subsection{pip and pipx}
\begin{ccode}
pipx install git+https://github.com/ARP273-ROSE/coupole\\
pip install .                 \# from the sources; pip install ".[qualite]" adds SEP\\
python -m coupole             \# interface; coupole --help: command line

Extras: \texttt{qualite} (SEP), \texttt{validation} (lxml, xisf: XSD validation and second reader), \texttt{gpu}

previous version being restored on failure. A pip/pipx installation shows the command to run. Settings, cache and
reports live outside the installation folder and survive updates:

\section{OHP image bank module}
\subsection{The bank}
« OHP student observations » gathers the images taken by the diploma's students at the Observatoire de
Haute-Provence: 7,989 FITS images on 8 October 2026, 166 objects under 194 names, 60 nights from 2015 to 2026,
78.0 GB; 1.20 m telescope (T120, 7,419 images, 1024 pixels of 0.77″, 13.1′ field) and the 50 cm IRIS robotic
telescope (570 images, 2048 pixels of 0.68″ or 4096 pixels of 0.46″, 23′ and 31′ fields). The images are already
calibrated (dark, flat) and astrometrically solved: \textbf{they must not be recalibrated}.

\subsection{Catalogue}
\capture{img/catalogue_en.png}{1.0}
The inventory comes from the Observatory's public TAP service (\texttt{http://tap-ufe.obspm.fr/tap}, table
\texttt{ivoa.obscore}, one synchronous ADQL query), kept in a cache; a snapshot is shipped for offline work.
\emph{Refresh the inventory} (Ctrl+R) queries the service again and flags new images and names (« new since … »).
Database names are grouped into canonical objects; selecting one or several objects lists their images on the
right, filtered by night, filter and doubtful dates; this list is the selection to process. The estimate gives the
volume to download, the expected output volume and the free space. Times are shown in UTC and in site time (hover:
also the user's time).

\subsection{Processing}
\capture{img/traitement_en.png}{1.0}
For each image, duplicates excluded:
\begin{enumerate}[leftmargin=*,itemsep=1pt]
\item download: at most 4 at once (3 by default), total rate capped (8 MB/s by default), User-Agent naming Coupole,
  resume by HTTP Range requests, checks of size (server and inventory), multiple of 2,880 bytes and \texttt{SIMPLE}
  card;
\item reading of the FITS cards as written and of the pixels; SHA-1 fingerprint of the pixels (exact duplicates);
\item astrometric solution check (section~\ref{sec:astrometrie});
\item fixed header (section~\ref{sec:entetes});
\item writing in the chosen format, reading back and pixel-by-pixel comparison;
\item at the end: sorting into stacks, \texttt{LOT.txt}, \texttt{INDEX\_LOTS.csv}, \texttt{\_traitement/journal.csv}.
\end{enumerate}
The state is kept in \texttt{\_traitement/etat.sqlite}: \emph{Stop} then \emph{Start} (or running the same command
again) resumes without redoing anything. A folder keeps the name language and format of its first run.
\emph{Keep duplicates} also processes what would be left out; \emph{Keep the original FITS} stores them in
\texttt{\_traitement/fits\_origine}.

\subsection{Astrometric solution}\label{sec:astrometrie}
Consistency checks, always made: solution present and readable; scale within 2~\% of the nominal one
(\texttt{XPIXSZ}/\texttt{FOCALLEN}) or of the night median; angle within 5° of the night median (modulo 180°);
centre within 1.5° of the object medoid (fixed) or 2° of the object-and-night medoid (moving). Medians and medoids
come from the whole inventory.

With ASTAP (optional), each image is also solved independently:
\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lX@{}}
\toprule
\textbf{Status} & \textbf{Meaning}\\
\midrule
confirmed & ASTAP finds the same centre within 10″ and the same scale within 1~\%.\\
validated & solution kept: checks pass, ASTAP silent (poor or crowded field, short exposure) or absent.\\
redone & missing or inconsistent solution replaced by ASTAP's (with SIP); the old one goes to HISTORY.\\
doubtful & checks fail and no ASTAP to decide: image stored apart.\\
failed & nothing usable: image stored in \texttt{\_sans\_solution\_astrometrique} (\texttt{\_no\_astrometric\_solution} with English names).\\
\bottomrule
\end{tabularx}
\end{center}

\subsection{Fixed headers}\label{sec:entetes}
All original cards are kept in order; every replaced value is copied into a \texttt{HISTORY original value: …}
card (French wording when names are in French).
\begin{center}\small
\begin{tabularx}{\linewidth}{@{}>{\ttfamily}lX@{}}
\toprule
\normalfont\textbf{Keyword} & \textbf{Fix}\\
\midrule
OBJECT & canonical name (database aliases merged).\\
FILTER, FILTSYS, FILTORIG & normalised filter (B, V, R, Ha, OIII, g, r, i, z), system (Johnson, Cousins, SDSS, Gunn, Narrowband), original value.\\
LATITUDE, LONGITUD & fixed \textbf{only when the swap is proven} (swapped values matching the site); correct: untouched; ambiguous: flagged, untouched. Idempotent.\\
SITELAT, SITELONG, SITEELEV & added when missing (MPC 511 site converted to WGS 84); present and consistent: kept; inconsistent: flagged.\\
RA, DEC, OBJCTRA, OBJCTDEC & true centre of the solution.\\
PIXSCALE, ORIENTAT & measured scale, position angle of the Y axis.\\
FOCALLEN, XPIXSZ & recomputed only when missing or inconsistent by more than 2~\%.\\
CTYPE1/2 & « -SIP » without coefficients (IRIS, PinPoint) brought back to TAN.\\
DATE-OBS, DATEDOUT & added when missing; \texttt{DATEDOUT = T} when the date is shared with another exposure.\\
XISFCONV & description of the conversion.\\
\bottomrule
\end{tabularx}
\end{center}
The \texttt{t\_min} column of the database equals \texttt{DATE-OBS} − exposure/2; \texttt{DATE-OBS} (exposure
start) prevails. A header date written in local time (whole-hour offset equal to the site time-zone offset against
\texttt{MJD-OBS}/\texttt{JD}, or a « night » exposure dated in daylight) is flagged in the log, never silently
fixed.

\subsection{Stacks}
\capture{img/lots_en.png}{0.9}
A stack gathers what is stacked together: same object, same instrument (T120, T120-bin1, T120-sCMOS, IRIS-2048,
IRIS-4096), same filter, and same field for a fixed object (all nights) or same night for a moving object.
\begin{ccode}
07\_Nebulae/NGC\_6888/field\_1\_T120/V/20250716-214427\_NGC\_6888\_V\_1s.xisf\\
01\_Asteroids/914\_Palisana/night\_2023-08-15\_T120/R/LOT.txt
\end{ccode}
\texttt{LOT.txt} (French then English) gives object, database names, instrument, filter, exposures and total
exposure, nights, mean centre, angle, solution status, doubtful dates and stacking advice (StarAlignment or
CometAlignment, rejection suited to the number of exposures). File names: UTC date and time of the exposure start,
object, filter, exposure; sorting by name = sorting in time. Names are safe under Windows.

\subsection{Online record (optional)}\label{sec:fiche}
\capture{img/fiche_en.png}{0.95}
When the Internet is available, the \emph{Online record} tab (or the button of the same name under the catalogue)
shows public information on the selected object:
\begin{itemize}
\item deep sky and stars: \textbf{SIMBAD} (CDS, Strasbourg) --- type, ICRS coordinates, magnitudes, parallax (and
the distance it gives when precise enough), preferred measured distance with its method and reference, radial
velocity and redshift, angular size, spectral and morphological types, other names; links to the SIMBAD page,
\textbf{Aladin Lite} (sky image centred on the object) and, for galaxies, \textbf{NED}; when SIMBAD does not know
the name, \textbf{Sesame} (CDS) also queries NED and VizieR;
\item asteroids, comets, trans-Neptunian objects: \textbf{JPL} Small-Body Database --- orbit class, near-Earth or
not, elements (a, e, i, q, Q, $\Omega$, $\omega$, period, epoch), diameter, albedo, rotation period, absolute
magnitude;
\item planets and NEOCP designations: no record (explanatory message).
\end{itemize}
\textbf{The identifier chosen by the service is always shown}: SIMBAD, for instance, attaches « NGC 6888 » to its
Wolf-Rayet star HD 192163; the record says so. A positive redshift can be sent to the Cosmology module
(\emph{Send this redshift to the Cosmology module} button).

\paragraph{Politeness and offline use.} Nothing is sent while the tab is hidden; one request per selected object
(after 0.6~s without another selection change), at most one per second and per service, 8~s timeout, Coupole's
User-Agent. Answers are kept for 30~days in Coupole's cache (\texttt{enligne.json}, with their date; « not found »
for one day). Offline, the last known record is shown with its date, otherwise a clear message; the rest of the
application never depends on it. The \emph{Query online services} box stops all requests. The addresses
(\texttt{simbad.base}, \texttt{simbad.page}, \texttt{aladin.page}, \texttt{ned.page}, \texttt{sbdb.page},
\texttt{resolution.sbdb}, \texttt{resolution.sesame}) are set like the other sources.

\section{ASTAP (optional)}
Without ASTAP, Coupole does everything else. ASTAP (Han Kleijn, MPL~2.0 licence,
\url{https://www.hnsky.org/astap.htm}) adds an independent check of each solution. It needs the program and one
star catalogue.

\capture{img/astap_en.png}{0.72}

\paragraph{Catalogue.} The official site states that for a field of 0.6° or more, D05, D20, D50 and D80 all suit,
and that dense catalogues serve small fields. The bank's fields range from 10.7′ (0.18°) to 31.4′ (0.52°):
\textbf{D80} is recommended (about 1.2 GB; catalogue of the reference processing, 6,888 solutions confirmed out of
7,625); D50 (about 0.9 GB) also suits IRIS.

\section{Output formats}
\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lXl@{}}
\toprule
\textbf{Format} & \textbf{Content} & \textbf{Readers}\\
\midrule
XISF (default) & Float32 in ADU, \texttt{bounds="-1000:65535"}; UInt16 for integer IRIS FITS; zstd+sh level 9 compression; \texttt{Observation:*}, \texttt{Instrument:*} properties & PixInsight\\
FITS \texttt{.fits.fz} & lossless tile compression: GZIP\_2 without quantization (floats), RICE\_1 (integers) & Siril, astropy, DS9\\
FITS & uncompressed float32 (or UInt16) & all\\
\bottomrule
\end{tabularx}
\end{center}
\textbf{XISF}: \texttt{bounds} sets the range PixInsight maps to [0,1] when opening: nothing to set, same scale for
every exposure; the −1,000 lower bound keeps the negative values of short calibrated exposures. Size: 36~\% of the
original FITS for the T120 (float64), 62~\% for IRIS. \textbf{Compressed FITS}: measured with astropy 8.0, RICE\_1
and HCOMPRESS\_1 quantize floats (one-ADU error, even with \texttt{quantize\_level=0}); only GZIP\_1 and GZIP\_2
without quantization restore floats bit for bit. \textbf{float32 FITS}: in PixInsight, set the FITS input range to
0–65,535 with \emph{Truncate}. For every format the difference to the original FITS stays below half a float32 ULP
(checked pixel by pixel).

\section{Image quality (optional)}
\capture{img/module_qualite_en.png}{1.0}
The module needs the SEP library (Source Extractor in Python, LGPL, about 1 MB); it never runs automatically
(\emph{Measure} button, \emph{Check image quality} box of the processing, or \cmd{coupole qualite FOLDER --write}).
Report per stack: \texttt{QUALITE.csv} and \texttt{QUALITE.txt}.

\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lXl@{}}
\toprule
\textbf{Measure} & \textbf{Method} & \textbf{Synthetic validation}\\
\midrule
FWHM & elliptical Moffat with free $\beta$ fitted to each isolated, unsaturated star (model integrated over the pixel); median & ≤ 0.4~\% (Gauss and Moffat, 2.5–8 px)\\
ellipticity & $1-b/a$ of the same fit & ± 0.02\\
3 × 3 map & medians per ninth of the field & order recovered\\
background, noise & SEP, 64 px mesh & 0.5~\%; 5~\%\\
gradient, residual & plane fitted to the background map; residual amplitude & gradient and vignetting recovered\\
saturated & peak above SATURATE/DATAMAX (else 60,000 ADU) & 5 out of 5\\
trails & objects with major axis ≥ 12 px and $a/b \ge 6$ & 1 out of 1, 0 false\\
SNR & only with the gain (EGAIN/GAIN) & given or absent\\
sampling & FWHM < 2 px, 2–5 px, > 5 px & —\\
\bottomrule
\end{tabularx}
\end{center}
On 14 IRIS images (12 nights, FWHM from 2.4 to 11.3 px), the measured FWHM and the one written by PinPoint in the
header correlate (r = 0.974), median ratio 1.046 (0.85 to 1.16): the two estimators differ (PinPoint's method is
not described). Not offered for lack of validation: mag/arcsec² (no zero point), dust-donut detection. A FWHM
growing towards an edge may come from the sensor, field curvature, collimation, but also from seeing, tracking or
focus: the map alone cannot tell.

\section{Spectra and series}
\capture{img/module_donnees_en.png}{1.0}
Formats read: FITS (1D image with a linear \texttt{CRVAL/CDELT/CRPIX} WCS axis, 1 × 1 × N radio cubes, binary
tables) and CSV or text in columns (optional header, unit in parentheses or brackets). Radio velocity:

1,420.405751768 MHz. The frame is that of the frequency axis (\texttt{SPECSYS}); no LSR or barycentric correction is
made implicitly. Formats of teaching radio antennas are added with a reader (CONTRIBUTING.md, « Adding a format »).

\section{Sites and times}
\capture{img/module_sites_en.png}{0.95}
Time is always kept in UTC (aware dates); the site's local time and the user's are shown as well. The « evening

\section{Cosmology}\label{sec:cosmo}
\capture{img/module_cosmo_en.png}{1.0}
The redshift $z$ of a distant object does not give « one » distance but several, all correct, answering different
questions. The module computes them in the $\Lambda$CDM model with
\[ E(z)^2 = \Omega_r(z)(1+z)^4 + \Omega_m(1+z)^3 + \Omega_k(1+z)^2 + \Omega_\Lambda, \qquad
   D_C = \frac{c}{H_0}\int_0^z\frac{dz'}{E(z')}, \]
radiation included (CMB photons and neutrinos, one of them massive, 0.06~eV).
\begin{center}
\begin{tabularx}{\linewidth}{@{}lX@{}}
\toprule
Quantity & Use \\
\midrule
$D_C$ line-of-sight comoving & present distance of the object; saturates at $\approx 46$~Gly (particle horizon)\\
$D_M$ transverse comoving & equals $D_C$ in a flat universe; enters $D_L$ and $D_A$\\
$D_L = (1+z)D_M$ & photometry: $F = L/(4\pi D_L^2)$; distance modulus $\mu = 5\log_{10}(D_L/10~\mathrm{pc})$\\
$D_A = D_M/(1+z)$ & sizes: $\theta = \ell/D_A$; scale in kpc per arcsecond; maximum near $z\approx1.6$\\
$c\,t_L$ & path travelled by the light (the most intuitive, the least physical)\\
$t_L$, age at $z$, $t_0$ & lookback time; check $t_L + t(z) = t_0$\\
$V_C$ & comoving volume out to $z$ (Hogg 1999, exact in curved universes too)\\
velocities & $cz$ (naive), relativistic Doppler (inappropriate), $H_0 D_C$ (the only correct one)\\
\bottomrule
\end{tabularx}
\end{center}

\paragraph{Parameters.} Planck 2018 by default ($H_0 = 67.66$, $\Omega_m = 0.3111$ incl. $\Omega_\nu = 0.00144$,
$T_0 = 2.7255$~K) with the $1\sigma$ uncertainty propagated from \emph{correlated} $H_0$ and $\Omega_m$
($\rho = -0.976$: ignoring it would overestimate the uncertainty) and, optionally, the comparison with SH0ES
($H_0 = 73.04$, Hubble tension). For comparison: Planck 2015, WMAP 9-year, a « textbook » $\Lambda$CDM
(70~/ 0.3~/ 0.7 without radiation) and a custom set ($H_0$, $\Omega_m$, $\Omega_k$, Planck 2018 radiation).
Ranges: $H_0$ from 40 to 100, $\Omega_m$ from 0.1 to 1, $\Omega_k$ from $-0.3$ to $0.3$ ($\pm 0.05$ for Planck
2018); an out-of-range value is \emph{refused with an explanation}, never silently corrected.

\paragraph{Input.} A $z$ (comma or point), one of the examples (M\,87, 3C\,273, $z = 1$, $z = 2.34$, ULAS J1120,
GN-z11, reionisation, CMB), or an object name: its redshift is requested from SIMBAD (tolerant naming: « m87 »,
« ngc4486 »; several candidates: you choose). $z \le 0$ (approaching object, like M\,31) gives no distance; below
$z = 0.03$ the object's peculiar velocity dominates (warning); beyond $z \approx 1090$ the universe is opaque. Table
and curves export to CSV (« ; », UTF-8; raw values in Mpc, Gyr, Gpc$^3$).

\paragraph{Origin and checks.} The computation core is taken from the same author's « cosmologie-redshift »
calculator (public repository \url{https://github.com/ARP273-ROSE/cosmologie-redshift}), with astropy.cosmology.
Before integration it was compared on 8 October 2026 with astropy and with an independent SageMath integration
(mpmath, 18 digits, exact Fermi-Dirac function for the neutrinos), from $z = 10^{-8}$ to 1100, for
$\Omega_k = 0, \pm0.01, \pm0.05$: relative deviation $\le 3\times10^{-6}$ on distances and $\le 2\times10^{-5}$ on
ages and $E(z)$ (Komatsu fit of the neutrinos in astropy); no bug. astropy's comoving volume, however, loses all
its digits at very small $z$ in curved universes (down to a negative volume): Coupole uses a series expansion there,
matched to the closed form. Scripts: \texttt{outils/verif\_cosmo/}.

\begin{ccode}
coupole cosmo 0.158 --shoes\\
coupole cosmo --object "3C 273"\\
coupole cosmo 1 2 3 --model wmap9 --csv results.csv\\
coupole cosmo --curves 0.001 1500 300 --csv curves.csv
\end{ccode}

\section{Evolution}\label{chap:evolutif}
\paragraph{Sources.} Addresses (TAP, collection, portal, download URL rewriting, resolvers, collection point,
repository, map tiles) are in \texttt{coupole/donnees/sources.json}. Three layers: shipped values; file published in
the repository, fetched at startup when newer and passing the shape check (known keys, types, domains from an
allow-list; no cryptographic signature); values forced by the user, never overwritten. Preferences > Sources: edit,
back to default, test. If the image server moves, \texttt{ohp.telechargement.de}/\texttt{vers} rewrites the URLs.
\paragraph{Classification.} Shipped table \texttt{data/classement.json} (194 checked names); published aliases; user
corrections (\emph{Correct the classification}, \cmd{coupole ohp classify}); name-shape rules; optional online
resolution (JPL SBDB, CDS Sesame), cached; grouping by position on a known fixed object; otherwise « unclassified ».
Every automatic classification is marked « to check ».
\paragraph{Database.} Extra ObsCore columns ignored, missing ones replaced by a default, unknown instruments and
filters stored apart, non-image data never flagged « daytime »; tested on simulated inventories.

\section{Incident reports and privacy}
At first launch Coupole asks whether it may send anonymous reports: installation, sign of life (once a day), crash,
native crash, frozen interface, written report. Content: version, system, processor, memory, graphics card, a random
installation identifier, error trace with the home folder replaced by « \textasciitilde », the user name masked and
deep paths shortened. Never a computer name, a user name or an image. Without consent nothing is sent: reports stay
in \texttt{\_rapports} in the settings folder. The choice can be changed (Help menu, \cmd{coupole reports
--enable|--disable}).

\section{Writing a module}
A module is a Python package with a \texttt{manifest.json} (identifier, version, French and English names, icon,
texts, graphical and command-line entry points), discovered in \texttt{coupole/modules/}, through the
\texttt{coupole.modules} entry point, or in the \texttt{modules/} folder of the settings. Texts through \texttt{tr()},
mandatory tooltips, long work off the GUI thread: see CONTRIBUTING.md.
