\section{Présentation}
Coupole est une application libre (GPL-3.0), écrite en Python 3.10+, qui fonctionne sous Windows, macOS et Linux,
avec une interface graphique (PyQt6) et une ligne de commande complète. Tout l'affichage existe en français et en
anglais ; la langue du système est détectée, et peut être imposée (menu \emph{Langue}, Préférences, ou
\cmd{--lang fr|en}).

\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lX@{}}
\toprule
\textbf{Module} & \textbf{Fonction}\\
\midrule
Banque OHP & Inventaire, catalogue, téléchargement, contrôle astrométrique, en-têtes corrigés, conversion, lots empilables, anomalies, carte du ciel.\\
Qualité des images & Facultatif. FWHM, ellipticité, fond, bruit, gradient, saturation, traînées, échantillonnage.\\
Spectres et séries & Lecture et tracé de données 1D (spectres radio, courbes de lumière, tables).\\
Cosmologie & Du redshift aux distances, âges, volume, module de distance, échelle (Planck 2018 et autres).\\
Sites et heures & Base des sites, carte OpenStreetMap, heure UTC et heure locale.\\
Ma machine & Diagnostic matériel ; exemple minimal de module.\\
\bottomrule
\end{tabularx}
\end{center}

Principes : tout travail long s'exécute hors du fil graphique (l'interface reste réactive, avec progression et
annulation) ; un traitement interrompu reprend où il s'est arrêté ; rien n'est supprimé sans trace ; aucune
donnée n'est envoyée sans accord ; les composants facultatifs (ASTAP, SEP, CuPy) peuvent manquer.

\section{Installation}
\subsection{Paquets tout compris}
Les paquets embarquent Python et toutes les bibliothèques (PyQt6, numpy, astropy, zstandard, lz4, SEP) : rien
d'autre n'est à installer. Ils se mettent à jour d'eux-mêmes. ASTAP reste facultatif et n'est pas inclus.

\begin{center}\small
\begin{tabularx}{\linewidth}{@{}l>{\ttfamily\small}lX@{}}
\toprule
\textbf{Système} & \textbf{\normalfont Fichier} & \textbf{Installation}\\
\midrule
Windows 10/11 64 bits & Coupole-Setup-x.y.z.exe & Double-clic. Avertissement SmartScreen au premier lancement (installeur non signé) : « Informations complémentaires », « Exécuter quand même ». Installation dans le profil, sans droit administrateur.\\
macOS Apple Silicon & Coupole-x.y.z-macos-arm64.dmg & Glisser Coupole dans Applications. Premier lancement : clic droit, « Ouvrir ».\\
macOS Intel & Coupole-x.y.z-macos-x86\_64.dmg & Idem.\\
Ubuntu / Debian x86\_64, ARM64 & coupole\_x.y.z\_amd64.deb & \texttt{sudo apt install ./coupole\_x.y.z\_amd64.deb} (\texttt{\_arm64.deb} sur ARM) : apt installe les bibliothèques système de Qt ; commande \texttt{coupole}, entrée de menu. Ubuntu 22.04 ou plus récent, Debian 12 ou plus récent. Désinstaller : \texttt{sudo apt remove coupole}.\\
Autre Linux x86\_64 / ARM64 & Coupole-x.y.z-linux-*.tar.gz & Décompresser, lancer \texttt{installer.sh} (copie dans \texttt{\textasciitilde/.local/share/coupole}, entrée de menu).\\
\bottomrule
\end{tabularx}
\end{center}

\subsection{Avec le Python de l'ordinateur}
Les scripts du dossier des sources cherchent un Python 3.10 ou plus récent, créent un environnement virtuel,
installent les dépendances et créent les lanceurs. Une seule question : Entrée pour confirmer (\cmd{--oui} /
\cmd{-Oui} pour l'omettre).
\begin{ccode}
sh install.sh                \# Linux, macOS\\
install.bat                  \# Windows (double-clic ; lance install.ps1)
\end{ccode}
Sans Python, ou sans le module \texttt{venv} (Debian : paquet \texttt{python3-venv}), le script le dit et indique
comment l'obtenir. Emplacements : Linux \texttt{\textasciitilde/.local/share/coupole/venv} et lanceurs dans
\texttt{\textasciitilde/.local/bin} ; macOS \texttt{\textasciitilde/Library/Application Support/Coupole/venv} et
\texttt{\textasciitilde/Applications/Coupole.app} ; Windows \texttt{\%LOCALAPPDATA\%\textbackslash
Programs\textbackslash CoupolePython} et raccourcis Bureau et menu Démarrer.

\subsection{pip et pipx}
\begin{ccode}
pipx install git+https://github.com/ARP273-ROSE/coupole\\
pip install .                 \# depuis les sources ; pip install ".[qualite]" ajoute SEP\\
python -m coupole             \# interface ; coupole --help : ligne de commande
\end{ccode}
Extras : \texttt{qualite} (SEP), \texttt{validation} (lxml, xisf : validation XSD et second lecteur),
\texttt{gpu} (CuPy), \texttt{test} (pytest).

\subsection{Mise à jour, désinstallation, données}\label{sec:donnees}
Les paquets vérifient au démarrage (désactivable) la dernière version publiée sur GitHub et proposent de
l'installer : seule l'archive du code (\texttt{coupole-app-x.y.z.zip}, environ 1 Mo) est téléchargée, extraite par
l'application, l'ancienne version étant restaurée en cas d'échec. Une installation par pip/pipx affiche la commande
à lancer. Le paquet \texttt{.deb} ne se met pas à jour par archive : ses fichiers (\texttt{/opt/coupole}) appartiennent à
dpkg ; Coupole signale la nouvelle version, donne l'adresse du nouveau \texttt{.deb} et la commande \texttt{apt} à
lancer (bouton \emph{Télécharger le paquet}). Les réglages, le cache et les rapports vivent hors du dossier
d'installation et survivent aux mises à jour comme à la désinstallation :

\begin{center}\small
\begin{tabular}{@{}ll@{}}
\toprule
Windows & \texttt{\%LOCALAPPDATA\%\textbackslash Coupole}\\
macOS & \texttt{\textasciitilde/Library/Application Support/Coupole} (cache : \texttt{\textasciitilde/Library/Caches/Coupole})\\
Linux & \texttt{\textasciitilde/.config/coupole} (cache : \texttt{\textasciitilde/.cache/coupole})\\
Tous & variable \texttt{COUPOLE\_HOME} : remplace les deux (installations portables, tests)\\
\bottomrule
\end{tabular}
\end{center}

\section{Prise en main}
La fenêtre comporte une barre de modules à gauche (Ctrl+1 à Ctrl+9) et le module courant à droite. Chaque élément
interactif porte une info-bulle. Menu \emph{Aide} : aide de l'écran affiché (F1), ce manuel (Maj+F1), raccourcis
clavier, signaler un problème, rapports d'incident, recherche de mise à jour, À propos (version, licence,
configuration détectée).

\begin{center}\small
\begin{tabular}{@{}ll@{}}
\toprule
F1 & aide de l'écran\\ Maj+F1 & manuel PDF\\ Ctrl+1 … Ctrl+9 & module 1 à 9\\ Ctrl+, & Préférences\\
Ctrl+Maj+A & assistant ASTAP\\ Ctrl+Maj+D & thème sombre / clair\\ Ctrl+R & Banque OHP : rafraîchir l'inventaire\\ Ctrl+Q & quitter\\
\bottomrule
\end{tabular}
\end{center}

\capture{img/reglages_fr.png}{0.62}
Préférences (Ctrl+,) : langue de l'interface ; langue des noms de dossiers, d'objets et des commentaires FITS ;
apparence (section~\ref{sec:apparence}) ; dossier de sortie ; format ; parallélisme ; débit maximal ; mode économe ; recherche de mise à jour ; vérification des nouveautés de la banque au démarrage et sa fréquence maximale (section~\ref{sec:nouveautes}). L'onglet
\emph{Sources} donne les adresses des services (chapitre~\ref{chap:evolutif}). Un fichier de réglages illisible est
mis de côté (suffixe \texttt{.corrompu-…}) et les valeurs par défaut reprennent : l'application démarre toujours.

\subsection{Apparence}\label{sec:apparence}
Coupole a son propre thème, indépendant de celui de l'ordinateur (un système en mode sombre ne mélange plus ses
couleurs à celles de l'application : style Fusion, palette complète, taille de police fixe, contraste WCAG $\geq$ 4,5
pour le texte, les champs, les boutons, les info-bulles et la sélection). Le thème \textbf{sombre} est celui par défaut ;
le thème clair reste au choix. Il se change par le menu \emph{Affichage} > \emph{Apparence} (entrées cochables
\emph{Clair} / \emph{Sombre}, Ctrl+Maj+D pour basculer), ou dans les Préférences : c'est le même réglage, appliqué
immédiatement et enregistré ; les deux restent synchronisés. Un utilisateur qui avait choisi le thème clair le garde :
le réglage enregistré prime sur le défaut. Les captures de ce manuel sont prises dans le thème par défaut.

\subsection{Réglages conservés}\label{sec:conserves}
Coupole retrouve à chaque lancement l'écran tel qu'on l'a laissé. Sont conservés :
\begin{itemize}
\item \textbf{fenêtre} : taille, position, écran, état maximisé ; taille de chaque dialogue (Préférences et son
  onglet, assistant ASTAP, À propos, signalement, aide, correction d'un objet, ajout d'un site) ;
\item \textbf{disposition} : module affiché, onglet de la Banque OHP, position des séparateurs, largeur et ordre des
  colonnes, colonne et sens du tri de chaque tableau ;
\item \textbf{Banque OHP} : recherche, type, télescope, cases \emph{Nouveaux}, \emph{À vérifier}, \emph{À télécharger
  seulement}, \emph{Sans dates douteuses}, nuit et filtre, objets choisis (rétablis dès que l'inventaire est chargé),
  filtres des anomalies et de la carte du ciel ; onglet Traitement : dossier de sortie \emph{dès qu'il est modifié},
  format, langue des noms, \emph{Garder les doublons}, \emph{Garder les FITS}, mode ASTAP, \emph{Vérifier la qualité} ;
\item \textbf{Qualité des images} : dossier analysé, mode échantillon et nombre d'images par lot ;
\item \textbf{Spectres et séries} : dossier du dialogue d'ouverture et menu \emph{Récents} (10 derniers fichiers ;
  un fichier disparu y est grisé) ; axe choisi ;
\item \textbf{Cosmologie} : jeu de paramètres, paramètres personnalisés ($H_0$, $\Omega_m$, gardés même en repassant
  par Planck), $\Omega_k$, $z$ courant, option SH0ES, échelle des courbes (logarithmique ou linéaire) ;
\item \textbf{Sites et heures} : site choisi, zoom et centre de la carte du monde, \emph{Carte en ligne} ;
\item \textbf{dialogues de fichiers} : chacun rouvre dans le dernier dossier utilisé (export CSV, réorganisation,
  ASTAP, signalement…).
\end{itemize}
La disposition vit dans \texttt{interface.json}, à côté de \texttt{reglages.json} (section~\ref{sec:donnees}) ; les
choix de traitement restent dans \texttt{reglages.json}. L'écriture est \emph{différée et groupée} : au plus une toutes
les 2~s et une à la fermeture, atomique (fichier temporaire puis remplacement) ; une frappe dans un champ n'écrit
jamais le disque. Lecture tolérante : une valeur absente, d'un mauvais type ou hors bornes laisse le défaut ; un
fichier illisible est mis de côté (\texttt{.corrompu-…}). Garde-fous : un écran débranché ou une position hors des
écrans recentre la fenêtre, une taille plus grande que l'écran est ramenée à l'écran (comme à 150 ou 200~\%). Un
dossier gardé sur un partage réseau absent ne bloque jamais le démarrage : son existence est vérifiée en fond, et le
dialogue s'ouvre au dossier par défaut tant qu'elle n'est pas confirmée. Rien de ce qui serait dangereux à rejouer
n'est gardé : un traitement interrompu n'est jamais relancé seul (il reprend quand on le relance).

Pour revenir à l'origine : Préférences > \emph{Réinitialiser la disposition} (immédiat ; la langue, le thème, le
dossier de sortie et les autres réglages ne changent pas), ou \cmd{coupole --reinitialiser-interface}
(\cmd{--reset-interface}).

\section{Module Banque OHP}
\subsection{La banque}
« OHP student observations » réunit les images prises par les étudiants du DU à l'Observatoire de Haute-Provence :
7~989 images FITS au 8 octobre 2026, 166 objets sous 194 noms, 60 nuits de 2015 à 2026, 78,0 Go ; télescope de
1,20 m (T120, 7~419 images, 1024 pixels de 0,77″, champ de 13,1′) et télescope robotique IRIS de 50 cm (570 images,
2048 pixels de 0,68″ ou 4096 pixels de 0,46″, champs de 23′ et 31′). Les images sont déjà calibrées (dark, flat) et
résolues astrométriquement : \textbf{elles ne doivent pas être recalibrées}.

\subsection{Catalogue}
\capture{img/catalogue_fr.png}{1.0}
L'inventaire vient du service TAP public de l'Observatoire (\texttt{http://tap-ufe.obspm.fr/tap}, table
\texttt{ivoa.obscore}, une requête ADQL synchrone), gardé en cache ; un instantané est livré pour travailler hors
ligne. \emph{Rafraîchir l'inventaire} (Ctrl+R) réinterroge le service et signale les images et les noms nouveaux
(« nouveau depuis le … »). Les noms de la base sont regroupés en objets canoniques ; la sélection d'un ou plusieurs
objets affiche leurs images à droite, filtrables par nuit, filtre et dates douteuses ; cette liste est la sélection
à traiter. L'estimation donne le volume à télécharger, le volume attendu en sortie et la place libre. Les heures
sont affichées en UTC et à l'heure du site (survol : également l'heure de l'utilisateur).

\paragraph{Ce qu'on possède déjà.} D'après le dossier de sortie (\texttt{\_traitement/etat.sqlite}, relu en fond à
l'ouverture, après chaque traitement et à chaque changement de dossier, jamais bloquant), la liste des images
distingue par une pastille et une couleur de texte douce (lisible dans les deux thèmes, contraste $\geq 4{,}5$) :
\textbf{possédée} (convertie et rangée, coche verte), \textbf{doublon écarté} (mêmes pixels qu'une image déjà
convertie, rond gris), \textbf{échec} (à retenter, triangle orange) et \textbf{à télécharger} (texte normal,
flèche) ; l'info-bulle de la pastille donne le statut, la date et le chemin local du fichier. Dans le tableau des
objets, la colonne \emph{possédé} (« 120 / 300 », mini-barre de progression, triable) et sa pastille (disque plein :
tout possédé ; demi-disque : en partie ; cercle vide : rien) résument chaque objet. La case \emph{À télécharger
seulement} cache les objets entièrement possédés et, dans la liste, les images déjà traitées ; l'estimation ne
compte alors que ce qui manque (« 180 images manquantes sur 300 : 1,5 Go »). Une légende compacte sous la liste
explique les pastilles. Ligne de commande : \cmd{coupole ohp inventaire --manquantes [--dest DOSSIER] [--json]}, et
colonnes \texttt{possedee}, \texttt{statut\_local}, \texttt{fichier\_local} dans le CSV de \cmd{coupole ohp images}.

\subsection{Traitement}
\capture{img/traitement_fr.png}{1.0}
Pour chaque image, hors doublons :
\begin{enumerate}[leftmargin=*,itemsep=1pt]
\item téléchargement : au plus 4 simultanés (3 par défaut), débit total plafonné (8 Mo/s par défaut), User-Agent
  identifiant Coupole, reprise par requêtes HTTP Range, contrôle de la taille (serveur et inventaire), du multiple
  de 2~880 octets et de la carte \texttt{SIMPLE} ;
\item lecture des cartes FITS telles qu'écrites et des pixels ; empreinte SHA-1 des pixels (doublons exacts) ;
\item contrôle de la solution astrométrique (section~\ref{sec:astrometrie}) ;
\item en-tête corrigé (section~\ref{sec:entetes}) ;
\item écriture au format choisi, relecture et comparaison pixel à pixel ;
\item à la fin : tri en lots, \texttt{LOT.txt}, \texttt{INDEX\_LOTS.csv}, \texttt{\_traitement/journal.csv}.
\end{enumerate}
L'état est gardé dans \texttt{\_traitement/etat.sqlite} : \emph{Arrêter} puis \emph{Lancer} (ou relancer la même
commande) reprend sans rien refaire. Un dossier garde la langue de noms et le format de son premier traitement.
\emph{Garder les doublons} traite aussi ce qui serait écarté ; \emph{Garder les FITS d'origine} les conserve dans
\texttt{\_traitement/fits\_origine}.

La chaîne est un \emph{pipeline} : les téléchargements (fils) et les conversions (processus séparés, un par cœur
disponible) se recouvrent, la file des FITS en attente est bornée ($2\times$ conversions + téléchargements ; si la
place libre à destination est juste, elle est réduite automatiquement — jamais sous conversions + 1 — et le journal le
dit, plutôt que de refuser le traitement), et le
débit global est celui du réseau ou du plafond choisi (mesuré : 24 images de 8 Mo à 8 Mo/s en 24,5 s, soit la durée
du seul téléchargement ; sans plafond, 86 Mo/s de FITS convertis sur 6 cœurs). \emph{Pause} suspend
l'alimentation du pipeline (les images en cours se terminent) et \emph{Reprendre} la rétablit ; \emph{Arrêter}
interrompt téléchargements et conversions sans attendre (les processus sont terminés, ASTAP compris : par signal
sous Linux et macOS, par un \emph{job object} sous Windows). À la fin, un
rapport résume images, durée, converties, doublons, échecs (avec leur raison), volume écrit et lots.

Sur un partage réseau (NAS par SMB), où chaque accès est un aller-retour, l'état est validé au plus une fois par
seconde et 	exttt{JOURNAL.txt} écrit par paquets (une coupure ne fait refaire que la dernière seconde) ; le rangement
final ne réécrit que les 	exttt{LOT.txt} qui ont changé et ne parcourt plus toute l'arborescence : relancer un
traitement pour une image ne coûte plus une minute de rangement.

\subsection{Tout télécharger, journal, réorganiser}\label{sec:tout}
\emph{Tout télécharger…} prend la banque entière (environ 8~000 images, 78 Go de FITS, 30 Go en XISF). Au premier
usage (ou si aucun dossier de sortie n'est défini), Coupole demande le dossier de destination par un dialogue natif et
propose \texttt{Documents/Coupole/OHP\_DU\_ECU} ; puis il affiche, \textbf{avant toute confirmation}, le volume à
télécharger, le volume attendu en sortie, la durée estimée au débit plafond (78 Go à 8 Mo/s : 2~h~42) et la place
libre ; il refuse clairement s'il en manque. Le traitement est celui de toute sélection : reprise après coupure ou
fermeture (état par image dans \texttt{\_traitement/etat.sqlite}, FITS déjà téléchargés retrouvés), pause, rapport
de fin. Ligne de commande : \cmd{coupole ohp tout --oui}.

\emph{Ouvrir le journal} affiche \texttt{\_traitement/JOURNAL.txt} : une ligne horodatée (UTC) et bilingue par
événement --- début et fin de session (reprise, pause), chaque image téléchargée, convertie ou écartée avec sa raison,
chaque erreur, chaque conflit de nom ; rotation à 5 Mo (\texttt{JOURNAL-1.txt}, \texttt{JOURNAL-2.txt}). Le détail
tabulaire reste dans \texttt{journal.csv}.

\emph{Réorganiser des fichiers…} range dans l'arborescence des lots des images déjà converties par Coupole qui se
trouvent ailleurs ou selon un ancien rangement : chaque fichier est reconnu par son en-tête (adresse d'origine
\texttt{OHP:Source:URL}, ou carte \texttt{HISTORY} « converti de … »), rattaché à l'inventaire et \textbf{déplacé}
(jamais copié) ; un nom déjà pris par un fichier étranger reçoit un suffixe et une ligne de journal ; rien n'est
jamais écrasé. Les en-têtes sont lus par plusieurs processus, la progression s'affiche (« 1 200 / 7 625 en-têtes
lus ») et \emph{Arrêter} interrompt la lecture (ce qui est déjà reconnu est rangé). Ligne de commande :
\cmd{coupole ohp reorganiser DOSSIER --dest DEST}.

\subsection{Nouveautés de la banque}\label{sec:nouveautes}
À l'ouverture (au plus une fois par jour, réglable, désactivable dans les Préférences), si Internet est disponible et
qu'une copie locale existe dans le dossier de sortie, Coupole compare l'inventaire TAP frais à la copie. S'il y a des
images nouvelles, un bandeau apparaît dans la Banque OHP (et un message dans la barre d'état) : « N nouvelles images
(M objets, X Go) depuis le JJ/MM --- Télécharger maintenant ? / Plus tard / Voir ». \emph{Télécharger} traite les
seules nouveautés dans la même arborescence ; \emph{Voir} filtre le catalogue ; rien n'est jamais téléchargé sans
accord explicite. Le bouton \emph{Vérifier les nouveautés} lance la comparaison à la demande. Ligne de commande :
\cmd{coupole ohp nouveautes} (liste) et \cmd{coupole ohp nouveautes --telecharger}.

\subsection{Solution astrométrique}\label{sec:astrometrie}
Contrôles de cohérence, toujours faits : solution présente et lisible ; échelle à moins de 2~\% de la nominale
(\texttt{XPIXSZ}/\texttt{FOCALLEN}) ou de la médiane de la nuit ; angle à moins de 5° de la médiane de la nuit
(modulo 180°) ; centre à moins de 1,5° du médoïde de l'objet (fixe) ou 2° du médoïde objet et nuit (mobile).
Médianes et médoïdes viennent de l'inventaire entier.

Avec ASTAP (facultatif), chaque image est en outre résolue indépendamment :
\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lX@{}}
\toprule
\textbf{Statut} & \textbf{Signification}\\
\midrule
confirmée & ASTAP retrouve le même centre à moins de 10″ et la même échelle à moins de 1~\%.\\
validée & solution gardée : contrôles bons, ASTAP muet (champ pauvre, trop dense, pose courte) ou absent.\\
refaite & solution absente ou incohérente, remplacée par celle d'ASTAP (avec SIP) ; l'ancienne passe en HISTORY.\\
douteuse & contrôles en échec et pas d'ASTAP pour trancher : image rangée à part.\\
échec & rien d'utilisable : image rangée dans \texttt{\_sans\_solution\_astrometrique}.\\
\bottomrule
\end{tabularx}
\end{center}

\subsection{En-têtes corrigés}\label{sec:entetes}
Toutes les cartes d'origine sont gardées dans l'ordre ; chaque valeur remplacée est recopiée dans une carte
\texttt{HISTORY valeur d'origine : …}.
\begin{center}\small
\begin{tabularx}{\linewidth}{@{}>{\ttfamily}lX@{}}
\toprule
\normalfont\textbf{Mot-clé} & \textbf{Correction}\\
\midrule
OBJECT & nom canonique (alias de la base fusionnés).\\
FILTER, FILTSYS, FILTORIG & filtre normalisé (B, V, R, Ha, OIII, g, r, i, z), système (Johnson, Cousins, SDSS, Gunn, Narrowband), valeur d'origine.\\
LATITUDE, LONGITUD & corrigées \textbf{seulement si l'inversion est démontrée} (valeurs échangées retombant sur le site) ; justes : intactes ; ambiguës : signalées, intactes. Opération idempotente.\\
SITELAT, SITELONG, SITEELEV & ajoutés s'ils manquent (site MPC 511 converti en WGS 84) ; présents et cohérents : gardés ; incohérents : signalés.\\
RA, DEC, OBJCTRA, OBJCTDEC & centre réel de la solution.\\
PIXSCALE, ORIENTAT & échelle mesurée, angle de position de l'axe Y.\\
FOCALLEN, XPIXSZ & recalculés seulement s'ils manquent ou sont incohérents de plus de 2~\%.\\

\subsection{Fiche en ligne (facultative)}\label{sec:fiche}
\capture{img/fiche_fr.png}{0.95}
Si Internet est disponible, l'onglet \emph{Fiche en ligne} (ou le bouton du même nom sous le catalogue) affiche des
informations publiques sur l'objet choisi :
\begin{itemize}
\item ciel profond et étoiles : \textbf{SIMBAD} (CDS, Strasbourg) --- type, coordonnées ICRS, magnitudes, parallaxe
(et la distance qu'elle donne quand elle est assez précise), distance mesurée préférée avec sa méthode et sa
référence, vitesse radiale et redshift, taille angulaire, types spectral et morphologique, autres noms ; liens
vers la page SIMBAD, \textbf{Aladin Lite} (image du ciel centrée sur l'objet) et, pour les galaxies, \textbf{NED} ;

\item astéroïdes, comètes, transneptuniens : base des petits corps du \textbf{JPL} (SBDB) --- classe orbitale,
géocroiseur ou non, éléments (a, e, i, q, Q, $\Omega$, $\omega$, période, époque), diamètre, albédo, période de

\item planètes et désignations NEOCP : pas de fiche (message explicatif).
\end{itemize}
\textbf{L'identifiant retenu est toujours affiché} : SIMBAD rattache par exemple « NGC 6888 » à son étoile
Wolf-Rayet HD 192163 ; la fiche le signale. Un redshift positif s'envoie au module Cosmologie (bouton \emph{Envoyer
ce redshift au module Cosmologie}).

\paragraph{Politesse et hors ligne.} Rien ne part tant que l'onglet n'est pas affiché ; une seule requête par
objet choisi (après 0,6~s sans autre changement de sélection), au plus une par seconde et par service, délai de
8~s, User-Agent de Coupole. Les réponses sont gardées 30~jours dans le cache de Coupole (\texttt{enligne.json},
avec leur date ; un « introuvable » un jour). Hors ligne, la dernière fiche connue s'affiche avec sa date, sinon un
message clair ; le reste de l'application n'en dépend jamais. La case \emph{Interroger les services en ligne} coupe
tout envoi. Les adresses (\texttt{simbad.base}, \texttt{simbad.page}, \texttt{aladin.page}, \texttt{ned.page},
\texttt{sbdb.page}, \texttt{resolution.sbdb}, \texttt{resolution.sesame}) se règlent comme les autres sources.

\section{Qualité des images (facultatif)}
\capture{img/module_qualite_fr.png}{1.0}
Le module demande la bibliothèque SEP (Source Extractor en Python, LGPL, environ 1 Mo) ; il n'est jamais lancé
automatiquement (bouton \emph{Mesurer}, case \emph{Vérifier la qualité des images} du traitement, ou
\cmd{coupole qualite DOSSIER --ecrire}). Rapport par lot : \texttt{QUALITE.csv} et \texttt{QUALITE.txt}.

\paragraph{Vitesse, reprise, échantillon.} Les mesures tournent dans des processus séparés (nombre donné par le plan
machine : cœurs, mémoire, mode économe et bridage des Préférences ; au plus 3 quand le dossier est sur un partage
réseau, détecté et signalé, car la lecture limite alors la vitesse), la lecture d'une image recouvrant le calcul des
autres ; l'interface reste libre, \emph{Arrêter} est immédiat. Chaque image mesurée est gardée aussitôt dans le
cache \texttt{\_traitement/qualite.sqlite} par (chemin, taille, date) et affichée ; le \texttt{QUALITE.csv} de son
lot (écriture atomique) est réécrit au plus toutes les 5~s et à la fin du lot ou de l'arrêt : relancer ne refait pas
ce qui est fait, fermer puis rouvrir reprend. Le dossier n'est parcouru qu'une fois (lecture des dossiers et des dates
en parallèle, cache lu en une requête) : relancer sur la banque entière déjà mesurée, par un partage, prend 2~s au
lieu de 72~s. Au-delà de 200 images, Coupole propose un \textbf{échantillon} de 5 images par lot (réparties dans
le temps : première, dernière, milieu…, réglable dans l'onglet et par \cmd{--echantillon N}), qui suffit à juger un
lot, ou \emph{Tout mesurer} avec la durée estimée d'après les 3 premières images ; la progression donne le temps
restant et le débit (images/min). Sur le NAS de l'auteur (Ryzen 5 8500G) : 1,21 → 0,33~s par image T120
(modèle de Moffat vectorisé, dérivées analytiques, 120 étoiles par image), soit la banque entière en une dizaine de
minutes sur 5 processus.

\section{Cosmologie}\label{sec:cosmo}
\capture{img/module_cosmo_fr.png}{1.0}
Le redshift $z$ d'un objet lointain ne donne pas « une » distance mais plusieurs, toutes justes, qui répondent à des
questions différentes. Le module les calcule dans le modèle $\Lambda$CDM avec
\[ E(z)^2 = \Omega_r(z)(1+z)^4 + \Omega_m(1+z)^3 + \Omega_k(1+z)^2 + \Omega_\Lambda, \qquad
   D_C = \frac{c}{H_0}\int_0^z\frac{dz'}{E(z')}, \]
rayonnement compris (photons du fond diffus et neutrinos, dont un massif de 0,06~eV).
\begin{center}
\begin{tabularx}{\linewidth}{@{}lX@{}}
\toprule
Grandeur & Usage \\
\midrule
$D_C$ comobile radiale & distance actuelle de l'objet ; sature à $\approx 46$~G\,al (horizon des particules)\\
$D_M$ comobile transverse & égale à $D_C$ si l'univers est plat ; entre dans $D_L$ et $D_A$\\
$D_L = (1+z)D_M$ & photométrie : $F = L/(4\pi D_L^2)$ ; module de distance $\mu = 5\log_{10}(D_L/10~\mathrm{pc})$\\
$D_A = D_M/(1+z)$ & tailles : $\theta = \ell/D_A$ ; échelle en kpc par seconde d'arc ; maximum vers $z\approx1{,}6$\\
$c\,t_L$ & chemin parcouru par la lumière (le plus intuitif, le moins physique)\\
$t_L$, âge à $z$, $t_0$ & temps de regard en arrière ; contrôle $t_L + t(z) = t_0$\\
$V_C$ & volume comobile jusqu'à $z$ (Hogg 1999, exact aussi en univers courbe)\\
vitesses & $cz$ (naïf), Doppler relativiste (inadapté), $H_0 D_C$ (la seule correcte)\\
\bottomrule
\end{tabularx}
\end{center}

\paragraph{Paramètres.} Planck 2018 par défaut ($H_0 = 67{,}66$, $\Omega_m = 0{,}3111$ dont $\Omega_\nu = 0{,}00144$,
$T_0 = 2{,}7255$~K) avec l'incertitude $1\sigma$ propagée depuis $H_0$ et $\Omega_m$ \emph{corrélés}
($\rho = -0{,}976$ : l'oublier surestimerait l'incertitude) et, au choix, la comparaison avec SH0ES
($H_0 = 73{,}04$, tension de Hubble). Pour comparer : Planck 2015, WMAP 9 ans, un $\Lambda$CDM « de manuel »
(70~/ 0,3~/ 0,7 sans rayonnement) et un jeu personnalisé ($H_0$, $\Omega_m$, $\Omega_k$, rayonnement de Planck 2018).
Plages : $H_0$ de 40 à 100, $\Omega_m$ de 0,1 à 1, $\Omega_k$ de $-0{,}3$ à $0{,}3$ ($\pm 0{,}05$ pour Planck 2018) ;
une valeur hors plage est \emph{refusée avec une explication}, jamais corrigée en silence.

\paragraph{Saisie.} Un $z$ (virgule ou point), un des exemples (M\,87, 3C\,273, $z = 1$, $z = 2{,}34$, ULAS J1120,
GN-z11, réionisation, fond diffus), ou un nom d'objet : son redshift est demandé à SIMBAD (nom tolérant :
« m87 », « ngc4486 » ; plusieurs candidats : vous choisissez). $z \le 0$ (objet qui s'approche, comme M\,31) ne donne
pas de distance ; sous $z = 0{,}03$ la vitesse propre de l'objet domine (avertissement) ; au-delà de $z \approx 1090$
l'univers est opaque. Tableau et courbes s'exportent en CSV (« ; », UTF-8 ; valeurs brutes en Mpc, Gyr, Gpc$^3$).

\paragraph{Curseur.} Sous le champ $z$, un curseur parcourt tout le domaine sur une échelle logarithmique
(de 0,001 à 1100, repères 0,01 / 0,1 / 1 / 10 / 100 / 1000). En glissant, le marqueur vertical des courbes et le
tableau des valeurs suivent en direct : les valeurs sont alors \emph{interpolées} sur la grille des courbes (300
points logarithmiques, écart typique $< 0{,}5$~\%, colonnes $\sigma$ et SH0ES suspendues) et la ligne d'état le dit ;
au relâchement, le calcul exact reprend. Flèches : pas fin (1~\% d'une décade) ; Page haut/bas : une décade. Le
champ $z$ et le curseur restent synchronisés dans les deux sens. Les courbes suivent le redimensionnement de la
fenêtre, y compris quand elles passent sous le tableau (fenêtre de moins de 1500 px de large) : la moitié de la
hauteur visible leur revient.

\paragraph{Origine et vérification.} Le noyau de calcul est repris du calculateur « cosmologie-redshift » du même
auteur (dépôt public \url{https://github.com/ARP273-ROSE/cosmologie-redshift}), avec astropy.cosmology. Avant
l'intégration, il a été comparé le 8 octobre 2026 à astropy et à une intégration indépendante sous SageMath
(mpmath, 18 chiffres, fonction de Fermi-Dirac exacte pour les neutrinos), de $z = 10^{-8}$ à 1100, pour
$\Omega_k = 0, \pm0{,}01, \pm0{,}05$ : écart relatif $\le 3\times10^{-6}$ sur les distances et
$\le 2\times10^{-5}$ sur les âges et $E(z)$ (ajustement de Komatsu des neutrinos dans astropy) ; aucun bug. Le
volume comobile d'astropy perd en revanche tous ses chiffres à très petit $z$ en univers courbe (jusqu'à un volume
négatif) : Coupole emploie là un développement limité, raccordé à la forme fermée. Scripts :
\texttt{outils/verif\_cosmo/}.

\begin{ccode}
coupole cosmo 0,158 --shoes\\
coupole cosmo --objet "3C 273"\\
coupole cosmo 1 2 3 --modele wmap9 --csv resultats.csv\\
coupole cosmo --courbes 0,001 1500 300 --csv courbes.csv
\end{ccode}

\section{Ligne de commande}

\section{Évolutivité}\label{chap:evolutif}
\paragraph{Sources.} Les adresses (TAP, collection, portail, réécriture des URL de téléchargement, résolveurs,
point de collecte, dépôt, tuiles de carte) sont dans \texttt{coupole/donnees/sources.json}. Trois couches : valeurs
livrées ; fichier publié dans le dépôt, récupéré au démarrage s'il est plus récent et passe le contrôle de forme
(clés connues, types, domaines d'une liste blanche ; pas de signature cryptographique) ; valeurs forcées par
l'utilisateur, jamais écrasées. Préférences > Sources : modifier, revenir au défaut, tester. Si le serveur des
images déménage, \texttt{ohp.telechargement.de}/\texttt{vers} réécrit les URL.
\paragraph{Classement.} Table livrée \texttt{data/classement.json} (194 noms vérifiés) ; alias publiés ; corrections
de l'utilisateur (\emph{Corriger le classement}, \cmd{coupole ohp classer}) ; règles sur la forme du nom ; résolution
en ligne facultative (JPL SBDB, CDS Sesame), en cache ; regroupement par position sur un objet fixe connu ; sinon
« non classé ». Tout classement automatique est marqué « à vérifier ».
\paragraph{Base.} Colonnes ObsCore en plus ignorées, en moins remplacées par une valeur par défaut, instruments et
filtres inconnus rangés à part, données non images jamais signalées « de jour » ; testé sur inventaires simulés.
\paragraph{Sécurité.} Aucun secret dans le dépôt ; fichier de sources distant et point de collecte en HTTPS
obligatoire, taille bornée, liste blanche de domaines ; archive de mise à jour téléchargée seulement depuis GitHub,
contrôlée avant extraction (chemins absolus ou « .. » refusés, liens symboliques refusés, taille dépliée et nombre de
membres bornés), remplacement avec retour arrière en cas d'échec ; XISF et FITS lus avec des bornes de taille ; noms
de dossiers construits depuis la base rendus sûrs (ASCII, caractères interdits, noms réservés de Windows, longueur) ;
ASTAP lancé sans interpréteur de commandes ; aucun \texttt{eval} ni \texttt{pickle} sur des données externes.

\section{Rapports d'incident et confidentialité}
Au premier lancement, Coupole demande s'il peut envoyer des rapports anonymes : installation, preuve de vie (une
fois par jour), plantage, crash natif, interface figée, signalement écrit. Contenu : version, système, processeur,
mémoire, carte graphique, identifiant d'installation tiré au hasard, trace d'erreur avec le dossier personnel
remplacé par « \textasciitilde », le nom d'utilisateur et le nom de la machine masqués et les chemins profonds
tronqués ; un rapport ne dépasse jamais 64 ko. Jamais de nom de machine, d'utilisateur, ni d'image. Sans accord, rien ne part : les rapports restent dans \texttt{\_rapports} du
dossier de réglages. Choix modifiable (menu Aide, \cmd{coupole rapports --activer|--desactiver}).

\section{Écrire un module}
Un module est un paquet Python avec un \texttt{manifest.json} (identifiant, version, nom en français et en anglais,
icône, textes, points d'entrée graphique et ligne de commande), découvert dans \texttt{coupole/modules/}, par point
d'entrée \texttt{coupole.modules}, ou dans le dossier \texttt{modules/} des réglages. Textes par \texttt{tr()},
info-bulles obligatoires, travail long hors du fil graphique : voir CONTRIBUTING.md.
